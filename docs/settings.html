配置说明

每个设置项是干什么的

按设置窗口从上到下的分区顺序。全部设置自动保存在 ~/Library/Application Support/MipadDPTouch/config.json，下次启动恢复；菜单栏和设置窗口是同一份状态的两个表面，改哪边都一样。

状态 窗口顶部

连接状态LIVE

当前设备状态：如实显示「运行中」「未运行」「等平板上线」，不粉饰。

事件计数COUNTERS

笔事件 / 点击 / 拖拽 / 滚动 实时计数，菜单栏「清零计数」可归零。笔到底有没有 responded，看这里最快。

权限 分步引导，只做一次

为什么必须分步STEP BY STEP

macOS 不允许程序自己给自己授权，所以必须你在系统设置里点两下。App 不会把两个弹窗糊你脸上 —— 上一步没完成，下一步是灰的，每秒对一次权限状态，完成第 ① 步第 ② 步自己亮起来。

① 辅助功能② 输入监控

① 辅助功能：允许合成点击与拖拽 —— 不开，笔能移光标但点了没反应。macOS 27 里它改名「设备控制和数据访问」，`隐私与安全性` 两个位置都找一下，哪个有开哪个。

② 输入监控：读取平板笔的原始数据 —— 不开，收不到任何笔事件。

立即重启 / 重新检测TCC

macOS 的权限判定发生在进程启动时，授权后点「立即重启」才生效（不用手动退出再打开）。「重新检测」则重新连一次，如实告诉你成没成。

更新 App 后权限失效？ 本 App 是 ad-hoc 签名，按代码哈希记身份，重新打包哈希必变 —— 关掉开关再开没用。终端重置再重启：tccutil reset Accessibility io.github.inyvn.xiaomi-dptouch + tccutil reset ListenEvent io.github.inyvn.xiaomi-dptouch。升级时 bundle id 故意不变，就是尽量别让你走到这一步。

笔的输入 手感主战场

按键绑定BINDINGS

一支笔能做的事按形态分成四类手势，每一类都能绑一个动作。默认就是一直以来的手感，所以升级过来不用改；改坏了点右上角「恢复默认」。

手势怎么算默认动作
轻点笔尖点一下就走左键单击
快速滑动一笔划过去（位移 ≥ 12px）滚动翻页
停住再滑笔尖先停住一小会儿，然后再划拖拽 · 移动窗口
停住不动笔尖停住又没划走，抬手时算右键菜单

可绑的动作：关 / 左键单击 / 右键菜单 / 中键单击 / 双击 / 滚动翻页 / 拖拽 / 空格键 / 返回 / 切换屏幕。同一个「拖拽」在两个手势下叫法不同 —— 绑在快速滑动上叫「拖拽 · 选中文字」（起手就划，快进快出划选一段），绑在停住再滑上叫「拖拽 · 移动窗口」（先按住在挪）。每一类手势只列出它真的做得到的那些（轻点没有位移，就绑不了滚动和拖拽）。

想每一笔都是拖拽？把「快速滑动」的动作改成「拖拽 · 选中文字」 —— 这就是老版本的「滑动选择」模式，现在不需要单独的开关了。

为什么划动不会误选文字？因为「滚动翻页」全程一个鼠标按键都不发 —— 不是「划完再取消选择」，而是压根没有「按住」这个状态。

切换屏幕 = 把光标基准屏换到下一块在线屏：顺序按桌面排列从左到右、到头绕回第一块，循环。只换笔的落点，不改任何一块屏的分辨率 / 排列 / 镜像；只接了一块屏时按了不动作（日志会写一句）。接了两块以上屏、又不想每次都去点菜单栏时，把它绑到一类手势上（例如「停住不动」）就行了。

组合起来就是一套自己的手感，例如：轻点 = 双击、停住不动 = 空格键（翻 PPT）、快速滑动 = 拖拽；多屏时「停住不动 = 切换屏幕」也很顺手。改完立即生效，不用重启。

默认跟随系统 —— 跟你 Mac「系统设置 → 鼠标/触控板 → 自然滚动」走的设置，你不需要理解原理。觉得方向反了，选「始终自然」或「始终传统」覆盖即可。

跟随系统（默认）始终自然始终传统
滚动速度SCROLL SPEED

运行 常用开关

启用笔桥接BRIDGE

总开关。临时停用不用拔线；菜单栏也有同名勾选项，两边状态同步。其余不常用的开关都在「高级选项…」小窗里。

显示缩放 只改平板那块屏

为什么会有这个功能WHY

平板面板原生 3408×2272（13.3″、308 ppi）。按 1x 直接送信号时逻辑 PPI ≈ 308，字比 MacBook Air 小 2.4 倍 —— 这就是「字太小」那档。直接拉低分辨率会糊：帧缓冲小于面板原生，平板要自己放大。

正确做法是切到系统已经生成好的 HiDPI 档（按 2x 渲染、再 1:1 送面板，画面仍是最锐的）：

档位UI 看起来帧缓冲（真实信号）逻辑 PPI锐度
1704×1136 @120Hz字大了一档，刚好顺手3408×2272（= 面板原生，1:1）≈154最锐，零放大
1280×853 @120Hz字更大2560×1706≈116被平板放大 1.33x，略软
3408×2272 1x（原状）字极小3408×2272≈3081:1 但几乎没法读
多屏安全的设计SAFETY

先用 EDID（厂商 25001 / 型号 4）+ 屏幕名认出平板，认不出就把整组变灰、什么都不做；多个屏都像平板 → 拒绝（宁可不动也不猜）。Mac 自带屏永不改——改坏了自己那块屏就没法点菜单自救。提交时只改目标屏的模式，不碰其他屏的分辨率、排列、镜像。

切换立即生效RESYNC

切档自动重建坐标基准（engine.resync_display()），笔的落点立刻对齐新尺寸，不用重启 App。档位持久生效，重启后仍是这一档。想回 1x 3408×2272 原生档要用「打开「显示器」设置…」在系统设置里选。

高级选项 独立小窗

为什么要单独一个小窗WHY

主窗口只留常用开关，不常用的都收进「高级选项…」—— 界面不至于一屏全是开关，也不至于把排查用的开关藏得找不到。状态与主窗口同一份，改完立即生效。

光标基准屏TARGET SCREEN

笔是绝对坐标设备：它报的是「笔尖在平板上的位置」，App 再把这个位置换算成某一块屏上的点 —— 换算到哪块屏就是这里选的。跟随光标（默认）不移动光标，光标在哪块屏笔就在那块屏上生效；选平板那块屏或任意一块在线屏时笔接管光标，一比一铺到那块屏上。

这就是让笔跨到别的屏上的办法：菜单里换一块屏即可，改完立即生效。指定的屏被拔掉时自动退回「跟随光标」（日志里有说明）。只改换算，不碰任何屏幕的设置、排列、镜像。

拖拽位置跟随笔尖DRAG SOURCE

拖拽时拿什么当落点。关（默认）= 以按下那一刻的光标为起点、跟着笔尖的位移走 —— 和「轻点」的落点一致；开 = 直接用笔尖在平板上的绝对位置，笔到哪就拖到哪。只在「拖拽的起点总是不对」时才需要开。

允许未验证的小米设备WHITELIST+

给未来机型的兜底开关。默认只匹配已实测设备（小米平板 9 Pro Max，VID 0x2717 / 0x18D1 / PID 0x2D05 + 笔接口 usage），避免误碰小米其它产品。如果你的小米平板也是 DP-in 且笔能移光标，打开它试试；能用欢迎提 issue 把型号加进白名单（src/dptouch_engine.py 的 KNOWN_DEVICES）。

允许管理未实测的显示器ALLOW+

多屏时「显示缩放」整组变灰说明没认出平板那块屏 —— 勾上这个才允许操作 EDID/名字不匹配的屏。这是防误触碰发的，确认列出来的是平板再开。

自动检查更新UPDATE

整个程序只有这一项会让它联网：启动后静默查一次 GitHub 上的最新版本，之后每天一次；查到了就弹窗告诉你有新版。关掉它就完全不联网。

更新流程是：下载 → 按发版正文里的 SHA256 校验 → 退出程序 → 替换 App（旧版先备份，任何一步失败都回滚）→ 重新打开。设置和日志都在你自己的 ~/Library/ 下，更新不动它们。只有查更新这一步会联网（api.github.com 查版本、github.com 取安装包）。

立即检查更新CHECK NOW

手动查一次。有新版本会给出更新说明和「下载并安装」；没有就告诉你已是最新；连不上 GitHub 会说清原因（这台机器上 github.com 有时不通，换网络再试）。

停住再滑 / 停住不动的判定时长THRESHOLDS

「停住再滑」默认 0.25s 算停住（四档：0.2 / 0.25 / 0.35 / 0.5s）；「停住不动」默认 0.8s（可 0.6 / 1.0s，选「关」则该手势不再触发）。太灵敏就调慢。停住之后又划走仍算拖拽，不会误弹菜单。

启动与日志

登录时自动启动LAUNCH AT LOGIN

登一下开关，登录后自动就绪。以系统实际状态为准并在旁边显示「已登记为登录项」；在「系统设置 → 通用 → 登录项」里可见、随时能关。

详细日志VERBOSE

排查用。开了之后日志会列出笔的坐标和系统光标的差值：差得明显 = 光标没跟上笔；差值为 0 却点不动 = 事件发出去了、系统没认。日志在 ~/Library/Logs/MipadDPTouch.log，只含笔事件计数，不含坐标历史和输入内容（App 不联网）。

诊断…SELFTEST

跑一遍自检，把结果写进日志。「什么都不对」时先点它。也支持无头自检，命令见 INSTALL.md。

隐私与卸载

PRIVACY

不联网，没有任何网络代码。只要两项最低权限：输入监控（读笔）+ 辅助功能（发鼠标事件）。卸载 = 菜单退出 → 删 App → 删 ~/Library/Application Support/MipadDPTouch/，没有残留服务。
